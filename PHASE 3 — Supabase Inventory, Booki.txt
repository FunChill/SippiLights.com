## AVAILABILITY LOGIC — src/lib/availability.ts
checkAvailability(date, requestedItems[]):
1. Reject if date in availability_blocks.
2. Pull bookings on that date with status pending_deposit or confirmed.
3. Sum qty per character+finish across those bookings.
4. For each requested item: available if qty_owned - booked_qty >= requested qty.
5. Return per-item availability + overall boolean.
Client-side call via anon key with a read-only RPC or view — do NOT expose full booking rows publicly. Create a Postgres function get_booked_quantities(check_date) returning only {character, finish, qty} aggregates. RLS: public can execute the function and insert inquiries; only authenticated (owner) can read/update bookings.
